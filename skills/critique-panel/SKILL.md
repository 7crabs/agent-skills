# 批判的レビュワーパネル

## 手順
1. レビュー対象を確定する。**成果物が会話内にしか存在しない場合は、まず一時ファイルに書き出してから渡す**（コールド起動の前提を満たすため）
2. 対象に合わせて3つ前後の観点を選ぶ。例:
   - プロダクト企画: ゲームデザイン / 行動経済学 / 競合分析
   - 設計・アーキテクチャ: 運用負荷 / 障害シナリオ / 代替案比較
   - ドキュメント: 初見の読者 / 反証可能性 / 抜け漏れ
3. 観点ごとにサブエージェントを**並列で**コールド起動する（先行文脈を渡さず、成果物と観点だけを渡す）
   - モデル指定が可能なハーネスでは、レビューの読み込み・列挙はトークン消費が大きいため、ユーザーがコスト重視を明言した場合は各レビュワーに安価なモデル（Sonnet等）を指定してよい。既定はメインセッションと同じモデル（指摘の質を優先）。統合・裁定（手順4以降）は常にメインセッション側で行う

   各レビュワーへの指示に必ず含める:
   - **ファイルの編集・作成は禁止（読み取り専用）**。可能なら読み取り専用エージェント（Explore等）を使う
   - お世辞・肯定的なまとめは不要。批判と具体的な改善案に集中する
   - 指摘には深刻度（致命的 / 重要 / 軽微）を付ける
   - 「ユーザー目線でどうか」を根拠付きで述べる。可能な限り実測・実行で検証する
4. 統合: 重複を除去し（複数レビュワーの一致は明記）、深刻度順に並べ、対立する指摘はトレードオフとして明示する。出力形式は指摘ごとに「深刻度 / 対象箇所 / 問題 / 改善案」で統一する
5. 修正は自動で適用しない。指摘一覧を提示し、どれを採用するかユーザーと検討する
