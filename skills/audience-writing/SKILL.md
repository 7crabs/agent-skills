# 他者向け成果物の執筆原則

**想定読者が指定されていなければ、書き始める前に確定する。** 候補（CDP チーム内 / 社内他チーム・Mgr・PdM / 社外パートナー / 複数）と自分の推測を推奨付きで提示し、ユーザーに選ばせる。ドラフトを先に出さない。

**読者はこのセッションを一切知らない。** セッション内で生まれた略語・ファイルパス・コミット・「先ほどの調査」といった参照は読者に意味を持たない。読者が CDP チーム外を含むなら PBI などチーム用語も定義が要り、社外を含むなら社内事情・個人名・内部ステータスは原則載せない。

**初稿は最小にする。** 知っていることを全部載せない。結論・根拠・次のアクションに絞り、詳細は求められたら足す。足すのは容易で、削るのはユーザーの手間になる。

## 過去の失敗（いずれもユーザーが手で削った）

- 作業メモで使った略語「エンジ起因」が提出物にそのまま伝播した
- Confluence 版に「リポジトリ内 doc/xxx.md にドラフトあり」「チームレビュー待ち」と内部参照を書いた
- レビューコメントに定量根拠や緊急性の強調を並べ、認知負荷を上げた。必要だったのは問題・提案・逃げ道の 3 点だけ

## 補助手段

先行文脈を渡さずに成果物ファイルだけを read-only サブエージェントに読ませ、意味不明な語や不要な段落を挙げてもらうと、私的用語を機械的に検出できる。
