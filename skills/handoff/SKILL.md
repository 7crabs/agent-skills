# 引き継ぎ資料を書く

1 つの作業を、複数のセッションで順に引き継いで進めるための資料を書く。書く材料は Claude の記憶ではなく会話記録にする。長いセッションで前半を忘れていても、コンテキストが溢れたセッションを閉じた後の新しいセッションからでも、同じ質で書ける。

## 2 つのディレクトリ

| | 中身 | 決め方 |
|---|---|---|
| **作業ディレクトリ** | セッションを開く場所。会話記録はここに紐づく | 今のディレクトリ |
| **資料ディレクトリ** | 引き継ぎ資料を置く場所 | 引数で指定されたもの。無ければ下の「初回」で決める |

- 作業ディレクトリがチームで共有するコードリポジトリなら、資料ディレクトリは**リポジトリの外**に置く。リポジトリに混ざらず、`git clean` や worktree の削除で消えない。セッションはいつものリポジトリで開くので、メモリも会話記録も 1 か所にまとまる
- 調査・企画のように作業用のディレクトリを作ったなら、資料ディレクトリは作業ディレクトリと同じでよい
- 次のセッションでは、ユーザーが資料ディレクトリの場所を伝える（`/handoff <資料ディレクトリ>` か「<パス>/HANDOFF.md を読んで続きから」）

## 書くもの（資料ディレクトリに置く）

| ファイル | 中身 | 書き方 |
|---|---|---|
| `HANDOFF.md` | 目的・現在地・次の一手・ユーザーに聞きたいこと・未完了 | 毎回上書きする。ただし「目的」はユーザーが変えると言ったときだけ変える。1 画面（40 行程度）に収める |
| `FACTS.md` | 確認できた事実 | 追記する。各項に出所（ファイル・URL・コマンド・誰の発言か）を付ける |
| `DECISIONS.md` | ユーザーが決めたこと | 追記する。**ユーザーの発言を引用できるものだけ** |

ほかのファイル（計画表・未確定リスト・ログなど）は作らない。資料ディレクトリと作業ディレクトリが同じときだけ、`CLAUDE.md` に「新しいセッションは `HANDOFF.md` から読む」の 1 行を足す（無ければその 1 行で作る）。コードリポジトリの `CLAUDE.md` には書かない。

## 手順

`transcript.sh` は常に `bash ~/.claude/skills/handoff/scripts/transcript.sh` の形で呼ぶ（インストール時に実行権限が付かないため）。

1. **資料ディレクトリを決める**：引数、なければ今のディレクトリに `HANDOFF.md` があればそこ。どちらも無ければ「初回」へ
2. **範囲を決める**：`HANDOFF.md` の「最終更新」より後の会話を対象にする。初回は全部。引数 `since` があればそれを使う。今の時刻を `transcript.sh now` で控える
3. **会話記録を読む**：読み込みはサブエージェントに任せ、メインのコンテキストを使わない。サブエージェントには次を渡す
   - 読み方：`transcript.sh --workdir <作業ディレクトリ> show --since <TS>`（決定の引用には `--user-only` も）
   - 今の `HANDOFF.md` / `FACTS.md` / `DECISIONS.md`
   - 下の「書き込みのルール」
   - 返してほしいもの：各ファイルへの追記・差し替えの案と、決定ごとの引用元（時刻とセッション ID）
4. **書く**：返ってきた案を確かめてから書き込む。引用が会話記録の文面と一致しない決定は書かない
5. **報告する**：次を並べる。ユーザーが違うと言ったものはその場で消す
   - 追加した決定（引用付き）
   - 追加した事実（出所付き）
   - 聞きたいこと
   - 対象外にした話題（あれば 1 行）

### 初回（資料ディレクトリに `HANDOFF.md` が無いとき）

1. **資料ディレクトリをユーザーに聞く**。作業ディレクトリがコードリポジトリなら、リポジトリの外の場所を提案する
2. **既存のファイルを確かめる**：資料ディレクトリに `FACTS.md` / `DECISIONS.md` / `CLAUDE.md` や、計画表・未確定リスト・ログなど別の形式の記録があれば、**書く前に止める**。食い違う点（読む順番の指示が 2 つになる、決定の形式や番号が混ざる、現在地が 2 か所になる等）を示し、どれにするかユーザーに選んでもらう
   - **移行する**：既存の内容を 3 つのファイルに寄せる。発言の引用が無い既存の決定は、`DECISIONS.md` の「移行前の記録（引用なし）」節にそのまま移し、書き換えない。古いファイルは、消してよいかユーザーに確かめてから消す
   - **既存の形式に合わせて追記する**
   - **やめる**
3. **目的を聞く**：目的・完了条件・範囲外・発端をユーザーに聞き、答えを言葉を変えずに書く。Claude が会話から推測して埋めない

### 会話記録が見つからない、または足りないとき

- 別のディレクトリで作業した可能性がある。`transcript.sh find <作業名・ディレクトリ名など>` で探し、見つかったセッションをユーザーに見せて、対象にするかを確かめる。対象にするなら `transcript.sh --dir <ディレクトリ> show --session <ID>` で読む
- それでも無ければ（別の PC で作業した等）、その旨を伝え、今のコンテキストにある分だけで書くかをユーザーに選んでもらう

## 書き込みのルール

- **決定**：ユーザーが決めたと言える発言を、文面を変えずに引用する
  - Claude の提案に「はい」「いいです」と答えた場合は、何に同意したかが会話から特定できるときだけ書く。提案の文と同意の発言の両方を引用する
  - 迷っている・考えている段階の発言（「〜かも」「迷いますね」）は決定にしない
  - 引用できないものは書かず、報告の「聞きたいこと」に回す
- **事実**：出所のあるものだけ。Claude の推測・解釈は書かない。推測は推測と書いて `HANDOFF.md` の現在地に置く
- **聞きたいこと**：3 件まで。目的の達成を止めているものだけにする。Claude の提案を並べる場所にしない
- **対象にする話題**：`HANDOFF.md` の目的に関係する会話だけ。同じ作業ディレクトリで別の作業をしていたら、その部分は書かない
- 会話記録にあるパスワード・トークン・個人情報は書き写さない

## 雛形

`HANDOFF.md`

```markdown
# HANDOFF：<作業名>
- 作業ディレクトリ：<パス>（会話記録はここに紐づく）
- 最終更新：<transcript.sh now の値>（これより後の会話が次回の対象）

## 目的
- 目的：
- 完了条件：
- 範囲外：
- 発端：（依頼元・リンク）

## 現在地
## 次の一手
## ユーザーに聞きたいこと
## 未完了
```

`FACTS.md`

```markdown
# FACTS
- <事実> [出所 / 確認日]
```

`DECISIONS.md`

```markdown
# DECISIONS
<!-- ユーザーの発言を引用できるものだけ書く -->

## D-001：<決めたこと>
- 日付：
- 発言：「<ユーザーの発言をそのまま>」（<時刻> / <セッション ID>）
- 補足：（背景・影響。必要なときだけ）
```
