# 会話記録から振り返る

印象ではなく、実際のやりとりから改善案を出す。目的は、次のセッションで同じ問題を起こさないこと。反映するのはユーザーが選んだものだけ。

会話記録は handoff スキルの `transcript.sh` で読む。常に `bash ~/.claude/skills/handoff/scripts/transcript.sh` の形で呼ぶ。handoff が入っていなければ、その旨を伝えて止める。

## 手順

1. **対象のセッションを選んでもらう**：`transcript.sh recent` の上から 4 件を選択肢にする（AskUserQuestion、複数選択）。ラベルはタイトル、説明に作業ディレクトリ・最後の発言の時刻・最初の発言。今のセッションも候補に含める。「その他」で「もっと見せて」と答えたら次の 4 件を出す。引数に観点（スキル名など）があれば控えておく
2. **場面を拾う**：読み込みはサブエージェントに任せ、メインのコンテキストを使わない。`transcript.sh --dir ~/.claude/projects/<記録のディレクトリ名> show --session <ID>` で、ユーザーと Claude の両方の発言を読ませる。拾う場面は次の順に重い
   1. ユーザーの訂正：「違う」「そうじゃなくて」、Claude の書いたものを直させた、Claude が言ったことを取り消した
   2. ユーザーの混乱・聞き返し：「あれ」「〜でしたっけ」「確認ですが」
   3. 同じ確認ややり直しの繰り返し
   4. スキルやツールの失敗と、その回避策
   5. ユーザーがはっきり評価した場面（残すべき動き）
   - 返してもらうもの：場面ごとに、時刻・セッション ID・ユーザーの発言の短い引用・何が起きたか
3. **原因と改善案をまとめる**：場面ごとに、原因と、直す場所（スキルのファイル・CLAUDE.md・メモリのどれか）と、具体的な変更案を書く
   - 原因が推測なら推測と書く
   - 最大 5 件。重い順に並べる
   - 関係するスキル・CLAUDE.md・メモリを読み、すでに書いてあることは案にしない。書いてあるのに守られなかったなら「書いてあるが守られなかった」として、書き方や置き場所の変更を案にする
4. **選んでもらう**：一覧を見せ、反映するものを選んでもらう（AskUserQuestion、複数選択）
5. **反映する**：選ばれたものだけ直し、差分を報告する
   - `gh skill install` などで入れたスキル（frontmatter に取得元がある）は、インストール先ではなく取得元のリポジトリを直す。直す場所をユーザーに確かめてから編集する

## ルール

- 改善案は 1 件ごとに、1 つの場所への具体的な変更にする。「気をつける」のような心がけにしない
- 問題が見つからなければ、そう報告して終える。件数を埋めない
- 引用は場面が分かる最小限にする。顧客名・個人情報・機微な情報は書き写さず、一般化する
- public リポジトリなど公開される場所に反映するときは、業務固有の情報を一般化してから書く
