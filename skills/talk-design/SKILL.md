# 発表の筋の設計

スライドより先に筋を決める。芯が無いまま見出しから直し始めると、直すたびに別の穴が出る。

## 進め方

- 段ごとに、決めることと理由を 1〜2 行で説明してから、質問を 1 つ出す。推測した答えを推奨として添え、ユーザーが確かめてから次へ進む
- 決まったことは設計ノート（既定は `TALK-PLAN.md`）に段の順で書き足す
- 前の段に戻ってよい。戻ったら後の段を見直す
- 材料（実測・出典）の無い主張は作らない。無ければ、調べる / 問いを変える / 次回に回す、をユーザーに選ばせる

## 段と合否

| 段 | 決めること | 合否 |
|---|---|---|
| 0. 形 | 依頼主の求める形（記録の展開 / 要約 / 発表）、聞き手、時間、回数。展開や要約で足りるなら、ここで終える。作業場所は元の調査と分ける | 形・聞き手・時間・回数を 1 行ずつ書けた |
| 1. 人物像 | 聞き手 2〜3 人分の、経歴 / 既に知っていること / 本人がやりたいこと / 配慮すること | 「やりたいこと」が発表者の関心の言い換えになっていない |
| 2. 答える問い | この回で答える問いを 1 文で書く。聞き手にとって答えが自明でなく、この時間と材料で答えられ、答えで見方か行動が変わるもの | 聞き手の誰かが「それは知っている」と言いそうにない |
| 3. 持ち帰り | 終わった後に聞き手が答えられる問いを 1〜2 個。「理解する」ではなく、確かめられる動詞（説明できる / 選べる）で書く | 答えの例を書ける |
| 4. 関係図 | 概念を丸、関係をラベル付きの線で描く（描ける環境なら図にして見せる）。描いてから話す順番を決める | 線がすべてラベル付き。新しい概念は 10〜15 分あたり 4 個前後まで |
| 5. 筋 | 2 を小さな問いに分け、答えを 1 本に並べる。同じ高さのものは、同じ親の問いに同じ役割で答える。示した原因には、対応を示すか次回の問いにする。別の筋を混ぜない | 答えだけを読んで話が通る。どれかを抜くと崩れる。入れ替えると通じない |
| 6. 絵コンテ | 各答えで見せる根拠（図・数字・表・コード）の下書きを描き、材料が手元にあるかを確かめる | すべての答えに、実在する材料がある |
| 7. 点検 | 人物像の名前で問う（「○○さんは、この問いがなぜ出たか分かるか」）。文脈を持たないサブエージェントに 2・3・5 だけを読ませ、筋の飛躍と内輪の用語を挙げさせる | 指摘を反映したか、しない理由を書いた |
| 8. 台本・スライド | 設計ノートを元に台本を書く。見出しは 5 の答えを主張の文にしたもの。画面の文字は読み上げず、見た目だけの図は入れない | — |

## 出典

- Greg Wilson『Teaching Tech Together』（CC BY-NC 4.0）https://teachtogether.tech/ — 人物像、持ち帰りからの逆算、関係図、一度に扱う量
- 安宅和人『イシューからはじめよ』（英治出版）— 答える問いを先に決める、ストーリーライン、絵コンテ（2 の条件は「良いイシューの 3 条件」を発表向けに読み替えたもの。本の内容は二次情報で確認）
- Barbara Minto『The Pyramid Principle』— 同じ高さのものの束ね方
- 5 の「抜くと崩れる・入れ替えると通じない」の点検は、公開スキル marcusnelson/presentation-writing-claude-skill の考え方による
